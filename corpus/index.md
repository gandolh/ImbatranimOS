- [research-remote-ui-rendering](wiki/research-remote-ui-rendering.md) — Research (2026-11-06) on the owner's idea of sending a Linux app's UI to the tab as a description the React desktop renders, instead of as pixels. Wayland carries finished buffers, so a description has to come from above it — the toolkit (GTK Broadway, Qt WebGL streaming), the app's accessibility tree (AT-SPI, Newton), the app compiled to WebAssembly (Qt, LibreOffice/ZetaOffice, egui, Greenfield), or a framework the app is written for (LiveView, Blazor Server, Shopify's remote-dom). Each option is compared on the phone keyboard, HiDPI, themes, accessibility, where input is handled, bandwidth, server memory and the apps it covers. Verdict: none is worth a prototype now. Broadway is deprecated and sends text as images, Qt's streaming plugin died with Qt 5, an accessibility tree can't draw documents or web pages, and WASM builds are canvases the 2026-10-21 office call rejected. The owner's real wants are cheaper to get inside today's pipeline: text-input-v3 for the phone keyboard (brief 45, drafted), brief 33 for HiDPI, and the Settings portal for colour scheme and accent.
